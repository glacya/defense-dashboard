# 데이터 관리 요령

이 프로젝트에서 데이터 파일과 전처리 스크립트를 다룰 때 지켜야 할 규칙입니다.

## 1. 샘플 데이터가 아닌 데이터는 Git에 올리지 않습니다

| 종류 | 설명 | Git 업로드 |
|---|---|---|
| 원본 데이터 | 데이터 제공처에서 받은 파일 | **금지** |
| 파생 데이터 | 원본을 가공해서 만든 파일 (전처리 결과물 등) | **금지** |
| 가상 데이터 | 직접 생성한 가상의 데이터 | **금지** |
| 샘플 데이터 | 위 데이터의 일부 (100행 내외) | **허용** |
| 컬럼 정의서 | 원본·통합 데이터의 컬럼 설명 | **허용** |

**이유**
- 공유 저장소의 용량을 줄입니다. 원본 데이터만 합쳐도 약 670MB입니다.
- 현재 사용하는 데이터셋은 CC-BY 라이선스로 공개된 데이터입니다. 그래도 원본 데이터를 공개 저장소에 그대로 올리지 않는 것이 좋은 관습이므로 이 규칙을 따릅니다.
- 가상 데이터 역시 실제 데이터처럼 취급하여 이 규칙을 따릅니다.
- 예외적으로 샘플 데이터는 업로드해도 좋습니다. 데이터의 실제 형태를 예시로 볼 수 있게 하기 위함입니다.

**커밋 전 확인**

`.gitignore`가 자동으로 제외하는 것은 아래 네 곳뿐입니다(`.gitkeep` 제외).
- `data/raw/*.csv`
- `data/intermediate/` 안의 모든 파일
- `data/processed/` 안의 모든 파일
- `data/synthetic/` 안의 모든 파일 (합성 단계가 만드는 가상 데이터)

이 밖의 위치에 데이터 파일을 만들었다면, 커밋하기 전에 `git status`로 그 파일이 목록에 올라와 있지 않은지 확인하세요.

### 파일 구성

- 범위: **202201 ~ 202607, 총 55개** (매월 1개)
- **2022년 5월분 주의**: KSPO 송파 일부 센터(`KSPO송파별관(어르신)`, `KSPO송파(출장B)`)의 2022년 5~6월 기록은 트레드밀 심박수가 거꾸로 입력되어 있습니다(데이터셋 댓글로 보고, 직접 확인함). 이런 행은 전처리 1단계의 "트레드밀 심박수 기입 오류" 규칙으로 제거되므로 5월분도 그대로 사용합니다.
- 컬럼 정의: `data/definitions/KS_NFA_RAW_DEFINITION.csv`

### 위치
55개 파일을 **모두 `data/raw/` 폴더에** 둡니다. 하위 폴더를 만들지 말고 바로 아래에 둡니다.

전처리는 `data/raw/`에서 **`KS_NFA_FTNESS_MESURE_*.csv` 이름 패턴에 맞는 파일만** 원본으로 읽습니다.
- 파일 이름은 받은 그대로 둡니다. 이름을 바꾸면 그 파일을 읽지 못합니다.
- `data/raw/`에는 원본만 둡니다. 샘플은 `data/samples/`에, 전처리 결과물은 `data/intermediate/`나 `data/processed/`에 둡니다.
- 다른 파일의 이름을 이 패턴으로 짓지 않습니다. 원본으로 잘못 읽혀 전처리가 실패하거나 결과가 오염됩니다.

## 4. 전처리 실행

data 파이프라인은 `data/scripts/main.py` 하나로 실행합니다. 순서는 **전처리 -> 합성 -> 분석**이고, 합성은 전처리가 끝난 데이터를 바탕으로 하므로 둘을 동시에 실행하지 않습니다. 영역 이름(`preprocessing`, `synthesis`, `analysis`)을 주면 그 영역만, 생략하거나 `all`을 주면 전체를 순서대로 실행합니다.

```powershell
conda run --no-capture-output -n kdt-project-1 python data/scripts/main.py                 # 전체
conda run --no-capture-output -n kdt-project-1 python data/scripts/main.py preprocessing   # 전처리만
```

> `--no-capture-output` 옵션을 빼면 Windows에서 한글을 출력하다가 `UnicodeEncodeError`가 날 수 있습니다. 이때 스크립트 작업 자체는 정상적으로 끝나지만, 종료 코드는 1로 나옵니다.

### 현재 전처리 순서

앞 단계의 결과가 다음 단계의 입력이 됩니다. 결과 파일이 여러 개인 단계는 `data/intermediate/` 아래에 단계별 폴더를 만들고, 통과한 행은 그 안의 `passed.csv`에 저장합니다.

| 순서 | 모듈 (`preprocessing/`) | 입력 | 출력 |
|---|---|---|---|
| 1 | `merge_raw_measurements` | 원본 55개 + 정의서 2개 | `intermediate/KS_NFA_MERGED.csv` |
| 2 | `build_prescription_details` | `KS_NFA_MERGED.csv` + PRESCRIPTION_DETAIL 정의서 | `processed/KS_NFA_PRESCRIPTION_DETAIL.csv` |
| 3 | `remove_missings_and_outliers` | `KS_NFA_MERGED.csv` | `intermediate/basic_refinement/` |
| 4 | `filter_enlistment_candidates` | `basic_refinement/passed.csv` | `intermediate/enlistment_filter/` |
| 5 | `select_three_measures` | `enlistment_filter/passed.csv` | `intermediate/KS_NFA_THREE_MEASURES.csv` |
| 6 | `apply_final_definition` | `KS_NFA_THREE_MEASURES.csv` + `KS_NFA_PRESCRIPTION_DETAIL.csv` + REFINED·PRESCRIPTION 정의서 | `intermediate/KS_NFA_REFINED.csv`, `processed/KS_NFA_PRESCRIPTION.csv` |

각 단계가 하는 일은 다음과 같습니다.
1. **원본 통합**: 19~24세 남성 행만 모으고(나이는 정수여야 하며, 비어 있거나 숫자가 아니거나 정수가 아닌 나이는 제외), 컬럼을 통합 정의서(`KS_NFA_MERGED_DEFINITION.csv`)대로 맞춥니다. BMI는 키와 체중으로 계산하고, 운동 처방은 본운동만 남깁니다. **심폐지구력**(`CARDIO`)은 세 종목(20m 왕복 오래달리기·트레드밀·스텝검사)의 VO₂max 출력 중 기록된 하나를 씁니다. 오래달리기도 횟수가 아니라 시스템이 환산한 VO₂max를 써서 세 종목의 단위를 맞춥니다. 두 종목 이상 기록된 행은 오래달리기 값을 쓰고, 확인할 수 있도록 `KS_NFA_MERGED_MULTI_CARDIO.csv`에 따로 저장합니다. 하나도 기록되지 않은 행은 빈칸으로 두어 다음 단계에서 결측으로 제거됩니다. BMI를 계산할 수 없는 행과 **트레드밀 심박수 기입 오류 행**(3분·6분 심박수가 모두 안정시 심박수보다 낮은 행)은 제거합니다. 심박수 컬럼은 결과에 남기지 않으므로 이 단계에서 판정합니다.
2. **운동 처방 상세 테이블 생성** (`KS_NFA_PRESCRIPTION_DETAIL.csv`): 원본 통합 결과 전체(걸러 내기 전)의 운동 처방 목록을 쉼표로 나눠, 서로 다른 처방 이름마다 처방유형번호를 처음 나온 순서대로 1부터 붙입니다(번호 순서에 의미는 없음). 걸러 내기 전 데이터로 만들므로 최종 측정에 쓰이지 않는 처방 이름도 들어 있습니다. 컬럼 구성은 `KS_NFA_PRESCRIPTION_DETAIL_DEFINITION.csv`를 따릅니다.
3. **결측치·이상치 제거**: 결측값이 있는 행을 먼저 제거하고(`removed_missing.csv`), 남은 행에서 이상치가 있는 행을 제거합니다(`removed_outlier.csv`). 이상치는 횟수 종목 `CROSS_UP`의 소수 기록과, 사람이 낼 수 없는 수준의 심폐지구력(`CARDIO`가 80 mL/kg/min 초과)입니다. 두 조건에 모두 걸린 행은 결측 파일에 들어갑니다. 운동 처방 `MVM_PRSCRPTN_CN`은 측정값이 아니므로 비어 있어도 제거하지 않습니다.
4. **입대 후보 조건 필터**: 키·체중·BMI·체지방률이 입대 후보 범위 안에 있는 행만 남깁니다.
5. **3회 이상 측정 회원 추출**: 필터를 통과한 기록 중 3회 이상 측정한 회원만 남기고, 회원마다 측정 기록 3건을 고릅니다. 측정 간격이 모두 30일 이상(`MIN_INTERVAL_DAYS`)인 3건 조합 중 전체 기간이 가장 길고 두 간격이 가장 고른 조합을 고르고, 고른 3건의 첫·마지막 측정이 3년(`MAX_SPAN_DAYS`)을 넘는 회원은 제외합니다. 같은 날 중복 입력된 기록은 간격이 0일이라 함께 뽑히지 않습니다. 필터를 모두 거친 뒤에 고르므로 최종 결과의 모든 회원은 정확히 3건씩 가집니다.
6. **최종 정의서 적용**: 측정일(`MESURE_DE`) → 회원식별번호(`M_CODE`) → 측정일련번호(`M_SEQ_NO`, 숫자 기준) 오름차순으로 정렬하고, 새 PK인 측정식별번호 `MESURE_ID`를 1부터 붙입니다. 원본에서는 (측정일, 회원식별번호, 측정일련번호)가 PK이므로 이 순서로 매긴 번호도 유일합니다. 그다음 두 파일로 나눠 저장합니다.
   - **측정 데이터** (`intermediate/KS_NFA_REFINED.csv`): 측정 컬럼 이름을 체력 요소 이름으로 바꾼 뒤(`REL_GRIP`→`STRENGTH` 근력, `CROSS_UP`→`ENDURANCE` 근지구력, `SIT_REACH`→`FLEXIBILITY` 유연성, `CARDIO` 심폐지구력은 그대로) `KS_NFA_REFINED_DEFINITION.csv`의 컬럼만 정의서 순서대로 남깁니다(현재 `MVM_PRSCRPTN_CN` 제외). 이 파일은 가상 장병 합성 단계의 입력이며, 합성 단계가 측정마다 그 회원의 군번(`SOLDIER_ID`)과 부상 위험 그룹 번호(`INJURY_RISK_GROUP_ID`)를 붙이고 `M_CODE`·`M_SEQ_NO`는 빼서 최종 측정 데이터(`processed/KS_NFA_PROCESSED.csv`, FINAL 정의서)를 만들고, 그룹별 기대 부상 건수는 `processed/INJURY_RISK_GROUP.csv`(`INJURY_RISK_GROUP_DEFINITION.csv`)에 둡니다.
   - **운동 처방 데이터** (`KS_NFA_PRESCRIPTION.csv`): 쉼표로 이어진 처방 목록(`MVM_PRSCRPTN_CN`)을 처방 하나당 한 행으로 나눕니다. 항목 앞뒤 공백은 지우고, 빈 항목과 같은 측정 안의 중복 처방은 만들지 않습니다(처음 나온 것만 남김). 처방식별번호 `PRESCRIPTION_ID`를 1부터 붙이고, `MESURE_ID`로 측정 데이터와 연결합니다. 같은 처방 이름이 수만 번 반복되므로 이름 대신 2단계 상세 테이블의 처방유형번호 `PRESCRIPTION_TYPE_ID`를 넣습니다(상세 테이블에 없는 이름이 있으면 오류). 컬럼 구성은 `KS_NFA_PRESCRIPTION_DEFINITION.csv`를 따릅니다.
   - 전처리 이후의 통계 작업은 이 두 정의서와 2단계의 PRESCRIPTION_DETAIL 정의서를 기준으로 합니다.

`remove_3sigma_outliers` 모듈은 현재 파이프라인에서 사용하지 않습니다. 데이터를 바꾸지 않는 분석 스크립트(공식 컷 등급 비율, 프로파일링 보고서)는 `data/scripts/analysis/`에 있습니다. 필요하면 아래처럼 단독으로 실행할 수 있습니다.

### 단계별 폴더

| 폴더 (`data/intermediate/`) | 파일 |
|---|---|
| `basic_refinement/` | `passed.csv`, `removed_missing.csv`, `removed_outlier.csv` |
| `enlistment_filter/` | `passed.csv`, `removed_missing.csv`, `removed_outlier.csv` |

제거 행 파일에는 `제거 사유` 컬럼이 붙습니다. 한 행이 여러 조건에 걸리면 한 파일에만 들어가고, `제거 사유`에는 걸린 조건이 모두 적힙니다.

### 단계 하나만 실행하기

각 단계 모듈은 단독으로 실행할 수 있습니다. 이때 입출력 경로는 `data/scripts/paths.py`의 기본 경로를 씁니다. 앞 단계의 결과 파일이 있어야 실행됩니다.

```powershell
conda run --no-capture-output -n kdt-project-1 python data/scripts/preprocessing/remove_missings_and_outliers.py
```

### 로그

실행 로그는 화면과 `data/scripts/logs/{yyyymmdd}_{hhmmss}_{실행한 모듈}.log`에 같은 내용으로 남습니다. `main.py`로 실행하면 `..._main.all.log`처럼 `main.{명령}`이, 단계를 단독으로 실행하면 `..._preprocessing.remove_missings_and_outliers.log`처럼 `data/scripts` 기준 `하위폴더.모듈` 이름이 붙습니다. 로그 각 줄에도 같은 형식으로 기록한 모듈이 찍힙니다. 단계별 입력·통과·제거 행 수가 기록되므로, 전처리 결과를 확인할 때 로그 파일을 보면 됩니다. 로그에 남는 경로는 프로젝트 루트 기준 상대 경로입니다.

## 5. 전처리 단계 작성 규칙

새 단계를 추가하거나 기존 단계를 고칠 때 지킵니다.

- **경로는 `data/scripts/paths.py`에, 단계 연결은 영역의 `pipeline.py`(전처리는 `preprocessing/pipeline.py`)에 둡니다.** 각 단계 모듈은 `run(입력 경로, 출력 경로)` 함수를 제공하고, 모듈 안에 경로를 직접 쓰지 않습니다.
- **단독 실행용 `main()`을 둡니다.** `paths.py`의 기본 경로로 `run()`을 호출하고, 로그 설정도 여기서 합니다.
  ```python
  # data/scripts/preprocessing/my_step.py
  from data.scripts.logging_setup import caller_name, setup_logging
  from data.scripts.paths import INTERMEDIATE_MERGED, INTERMEDIATE_MY_STEP

  def run(input_path: Path, output_dir: Path) -> None:
      ...

  def main() -> None:
      """data/scripts/paths.py의 기본 경로로 이 단계만 실행합니다."""
      setup_logging(caller_name(__file__))
      run(INTERMEDIATE_MERGED, INTERMEDIATE_MY_STEP)

  if __name__ == "__main__":
      main()
  ```
- **단계 추가**는 `paths.py`에 경로를 추가하고 영역의 `pipeline.py`의 `build_steps()` 목록에 `Step`을 추가하는 것으로 끝납니다.
- **결과 파일이 여러 개인 단계는 `output_dir`을 받아** 그 안에 `passed.csv`(`paths.PASSED_FILENAME`)와 `removed_*.csv`를 저장합니다. 출력 폴더는 단계 안에서 만듭니다.
- **`print` 대신 로거를 씁니다.** 모듈 맨 위에 `logger = logging.getLogger(__name__)`를 두고, 행을 제거하면 몇 행을 왜 제거했는지 `logger.info`로 남깁니다.
- **실패하면 예외를 던집니다.** `sys.exit()`를 쓰면 실행기(`data/scripts/pipeline.py`)가 어느 단계에서 실패했는지 기록할 수 없습니다.
- **행을 제거하는 단계는 "통과 + 제거 = 입력" 행 수를 검사합니다.** 맞지 않으면 예외를 던집니다.
- **파생 데이터 파일은 `data/raw` 폴더에 두면 안 됩니다.** 원본 파일로 잘못 인식되어 다음 전처리 때 원본과 함께 읽힙니다.
- **CSV 컬럼 이름은 언제나 영문입니다.** 저장하는 CSV(중간 결과 포함)의 컬럼 이름은 정의서의 `영문속성명` 같은 영문 대문자 이름을 쓰고, 코드 안에서도 한글 컬럼 이름으로 바꿨다가 되돌리지 않습니다. 값(예: `상지(상체)`, `전방`)은 한글이어도 됩니다. 한글 이름은 정의서의 `컬럼한글명`과 화면·로그 표시에만 씁니다. 원본 데이터의 컬럼 이름은 받은 그대로 둡니다.
- 여러 모듈이 함께 쓰는 코드는 `data/scripts/utils.py`에 둡니다. CSV 읽기·쓰기(`read_text_csv`, `write_csv`), 필수 컬럼 검사(`require_columns`), 정의서 컬럼 읽기·고르기(`load_definition_columns`, `select_definition_columns`, `write_by_definition`), 명령줄 인자 타입(`non_negative_float`, `positive_int`)이 있습니다.
- CSV는 `dtype=str, keep_default_na=False`로 읽고 `encoding="utf-8-sig"`로 저장합니다(`read_text_csv`, `write_csv`가 이 규칙대로 읽고 씁니다. 원본처럼 인코딩이 섞인 파일이나 숫자로 읽어야 하는 프로파일링은 예외). 빈 칸을 NaN이 아닌 빈 문자열로 유지하고, Excel에서 한글이 깨지지 않게 하기 위함입니다.
- 그 밖의 코드 작성 규칙은 [모듈 작성 요령](모듈-작성-요령.md)을 따릅니다.
