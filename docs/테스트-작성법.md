# 테스트 작성법

이 프로젝트는 [pytest](https://docs.pytest.org/)로 테스트합니다. 이 문서는 테스트를 작성하고 실행하는 데 필요한 기본 내용만 다룹니다.

## 1. 테스트 위치와 이름 규칙

테스트는 루트의 `tests/` 폴더에 둡니다. 테스트 대상 코드가 있는 위치에 맞춰 하위 폴더를 고릅니다.

```
tests/
├── dashboard/   # dashboard/ 코드에 대한 테스트
├── data/        # data/ 가공 스크립트에 대한 테스트
└── utils/       # 공용 유틸리티에 대한 테스트
```

pytest는 아래 규칙에 맞는 것만 테스트로 인식합니다. 이름이 규칙에 맞지 않으면 **에러 없이 조용히 무시**되므로 주의하세요.

| 대상 | 규칙 | 예시 |
|---|---|---|
| 파일 | `test_`로 시작 | `test_loader.py` |
| 함수 | `test`로 시작 | `def test_load_csv():` |
| 클래스 (선택) | `Test`로 시작, `__init__` 없음 | `class TestLoader:` |

서로 다른 폴더라면 파일 이름이 같아도 괜찮습니다. 예를 들어 `tests/dashboard/test_app.py`와 `tests/data/test_app.py`가 함께 있어도 됩니다.

## 2. 기본 작성법

`assert` 뒤에 참이어야 하는 조건을 씁니다. 조건이 거짓이면 테스트가 실패하고, pytest가 실제 값과 기대 값을 비교해서 보여줍니다.

```python
# tests/utils/test_example.py
from config import CSV_DATA_DIR


def add(a, b):
    return a + b


def test_add():
    assert add(1, 2) == 3


def test_csv_dir_exists():
    assert CSV_DATA_DIR.exists()
```

- 프로젝트 코드는 루트 기준 경로로 import합니다. 예: `from config import ...`, `from dashboard.py.loader import ...`
- 테스트 하나에는 확인할 내용 하나만 담습니다. 테스트 이름만 보고도 무엇이 깨졌는지 알 수 있어야 합니다.
- 테스트끼리 서로 의존하면 안 됩니다. 실행 순서가 바뀌어도 결과가 같아야 합니다.

## 3. 자주 쓰는 기능

### 예외가 발생하는지 확인: `pytest.raises`

```python
import pytest


def divide(a, b):
    return a / b


def test_divide_by_zero():
    with pytest.raises(ZeroDivisionError):
        divide(1, 0)
```

> `@safe_execution`이 붙은 함수(`dashboard/py/loader.py` 등)는 예외를 내부에서 처리하고 `None`을 반환합니다. 이런 함수는 `pytest.raises` 대신 `assert result is None`으로 확인하세요.

### 여러 입력으로 같은 테스트 반복: `pytest.mark.parametrize`

```python
import pytest


@pytest.mark.parametrize("a, b, expected", [
    (1, 2, 3),
    (0, 0, 0),
    (-1, 1, 0),
])
def test_add(a, b, expected):
    assert add(a, b) == expected
```

### 임시 파일과 폴더: `tmp_path`

테스트 함수의 인자에 `tmp_path`를 적으면 테스트마다 새 임시 폴더를 받습니다. 실제 `data/` 폴더의 파일은 테스트에서 수정하지 마세요.

```python
import pandas as pd


def test_read_csv(tmp_path):
    csv_file = tmp_path / "sample.csv"
    csv_file.write_text("이름,점수\n홍길동,90\n", encoding="utf-8")

    df = pd.read_csv(csv_file)

    assert len(df) == 1
    assert df.loc[0, "점수"] == 90
```

### 환경변수나 함수를 임시로 바꾸기: `monkeypatch`

API 키처럼 실행 환경에 따라 달라지는 값이나 외부 서비스 호출은 테스트 동안만 바꿔 둡니다. 테스트가 끝나면 원래대로 돌아옵니다.

```python
def test_without_api_key(monkeypatch):
    monkeypatch.delenv("GEMINI_API_KEY", raising=False)
    ...
```

> 테스트가 실제 Oracle DB나 Gemini API를 호출하면 안 됩니다. 네트워크나 계정이 없는 환경(CI 등)에서는 항상 실패하기 때문입니다. 이런 호출은 `monkeypatch`로 가짜 함수로 바꿔서 테스트하세요.

## 4. 마커 (`@pytest.mark.xxx`)

**아직 사용할 수 없습니다.** 등록되지 않은 마커를 쓰면 테스트가 에러로 중단됩니다.

단, 3절의 `@pytest.mark.parametrize`는 pytest에 내장된 기능이라 사용할 수 있습니다.

## 5. 실행 방법

항상 **프로젝트 루트**에서 실행합니다.

```powershell
# 전체 테스트
conda run -n kdt-project-1 pytest

# 특정 폴더 또는 파일만
conda run -n kdt-project-1 pytest tests/dashboard
conda run -n kdt-project-1 pytest tests/dashboard/test_loader.py

# 특정 테스트 함수만
conda run -n kdt-project-1 pytest tests/dashboard/test_loader.py::test_divide_by_zero

# 이름에 특정 단어가 들어간 테스트만
conda run -n kdt-project-1 pytest -k csv
```

`kdt-project-1` 환경을 활성화한 상태(`conda activate kdt-project-1`)라면 `pytest`만 입력해도 됩니다.

### 결과 읽기

| 표시 | 의미 |
|---|---|
| `PASSED` | 통과 |
| `FAILED` | `assert`가 실패함. 아래에 실제 값과 기대 값이 나옵니다. |
| `ERROR` | 테스트 실행 전 준비 단계에서 에러가 남. import 실패가 흔한 원인입니다. |
| `no tests ran` | 테스트를 하나도 찾지 못함. 1절의 이름 규칙을 확인하세요. |
